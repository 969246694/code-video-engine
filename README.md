# AI 科普短片系列

每一期的**配音、字幕、时间轴、排版、动效、编码全部由代码生成**，没有剪辑软件参与。

| 期数 | 版本 | 时长 | 画面 | 镜头 |
|---|---|---|---|---|
| 第 1 期 | 单版式 | 60.73s | 程序化渐变 + 网格 | 6 个场景 |
| 第 2 期 | 单版式 | 61.87s | AI 生成 6 张底图 | 6 个场景 |
| 第 2 期 | **多镜头剪辑版** | 62.00s | AI 底图 + 多镜头重构 | **19 个镜头** |

## 两套渲染引擎

这个项目里有两个并列的引擎，代表两种做法：

| | `render.py`（旧） | `ae.py` + `shots.py`（新） |
|---|---|---|
| 模型 | 每场景一张静止版式 | 合成 → 图层 → **一切皆可关键帧** |
| 运动 | 元素入场后定住 | 摄像机 + 表达式，全程在动 |
| 段落 | 1 场景 = 1 版式 | 1 场景 = 3-4 个镜头 |
| 实测平稳期运动 | **0.000（完全静止）** | **0.497（一直在动）** |
| 平均镜头长度 | 10.3s | **3.18s** |

新引擎的对外能力见 `ae.py`：关键帧（9 条命名缓动 + 自定义贝塞尔）、表达式
（wiggle / drift / constant_move）、图层变换、混合模式、**摄像机**、
**景深**（按图层 z 值算虚化）、**运动模糊**（单帧内时间子采样）、
**调整图层**（blur / levels / exposure / saturation / tint / vignette）、
**图片图层**（同一底图可多镜头取景）、合成嵌套。

`shots.py` 是**镜头库**：把"一个镜头"做成函数（给定文案与时长返回一个合成），
整期视频就是"从镜头库里挑镜头、排时间轴"。

# 第 2 期 · 多镜头剪辑版（当前主力）

长片的平均镜头长度是 4-6 秒，短视频 2-3 秒。
**所以"加镜头"的收益远大于"把单帧做得更漂亮"。**

实测对照（同一段 11.5 秒内容，同一套判据）：

| | 旧（单版式） | 新（多镜头） |
|---|---|---|
| 镜头数 | 6 | **19** |
| 平均镜头长度 | 10.3s | **3.18s** |
| 镜头内逐帧变化均值 | 0.045 | **0.799** |
| 平稳期变化 | **0.000** | **0.291** |
| 切点强度 / 镜头内运动 | — | **27×** |

## 验收

```bash
python build_cut.py --ss=1.5      # 构建（约 30 分钟）
python build_cut.py --preview     # 只出 19 张镜头静帧
python verify_cut.py              # 验收：节奏 / 对齐 / 运动 / 字幕
python make_contact_sheet.py      # 19 张静帧拼成联络表，一次性看构图
```

`verify_cut.py` 的判据（都是量化的）：
镜头数 15-24、平均镜头长度 2.5-4s、最短 ≥1.5s、最长 ≤6s、
每场景镜头组起止 == 旁白起止、镜头内平均运动 >0.05、无完全静止帧、
**切点强度 > 镜头内运动的 3 倍**、字幕覆盖 >95%、同一时刻只有一条字幕可显示。

## 踩过的坑（都写进注释了）

**① 场景之间的 0.28s 缝隙没有任何镜头覆盖。**
`SCENE_SPANS` 给的是**旁白**起止，场景之间还有 0.28s 静音间隔。
早期版本只让镜头覆盖旁白区间，那 0.28s 不属于任何镜头，
`render_frame` 落到"尾部兜底"分支，**错误地渲染最后一个镜头** ——
实测 107 帧（约 3.6 秒）画面上是结尾镜头，却穿插在全片各处。
现在每个镜头的结束时间顺延到下一个镜头起点，保证时间轴上任何时刻都有确定归属。

**② 字幕判定用了容差窗口，导致"同一时刻命中两条"。**
`caption_at` 原先用 `[start-0.10, end+0.35]`，只要相邻字幕间隔 <0.45s 就会双命中
（实测 371 帧）。虽然函数只返回第一条、画面不会真显示两行，
但后一条会被推迟 0.35s，破坏了与旁白的严格对齐。现在改为严格区间，
并在 `narrate.py` 里裁掉相邻字幕几十毫秒的重叠。

**③ `Layer.scale` 是百分比（100=原始），不是比例。**
`bar_layer` 曾写成 `scale_x.set(0.95)`，被当成 0.95%，680px 的概率条画成 6px 细线，
画面里"什么都没有"。现在 `ae._check_scale` 会自动识别 0<v≤4 的值并换算，同时打警告。

**④ 测量口径错误会得出相反结论。**
- 用 4× 降采样测运动量，暗底图上的微动被取整成 0 → 误报"23% 近静止"
- 把片头 0.45s 的静止定格算进"镜头内运动" → 误报 149 帧全静止
两处都是**测量方法**的问题，不是画面的问题。改动测量代码前先想清楚口径。

**⑤ `getlength` 与逐字绘制口径不同。**
`getlength(整串)` 含字距调整（kerning），而绘制是逐字画的、不含 kerning，
于是实际墨迹比预留宽度宽，相邻词条互相压上（实测 "AI" 与"最危险的时候" 重叠 19px）。
所有宽度计算统一改成逐字累加。

# AI 背景图

### 硬性约束（用户明确要求，务必遵守）

1. **只能用 `gpt`（GPT Image 2）**，不用 `nanobanana`
2. **禁止任何形式的图生图** —— 不传 `reference_image` / `reference_images` / `edit_image`。
   参考图会导致质量大幅下降、画面出现破绽
3. 只用文生图（text-to-image）

### 生成与接入

```bash
# 生成（MCP 工具，model="gpt"，不传参考图）
#   batch_generate_images(images=[{name, prompt, aspect_ratio:"16:9",
#                                  target_size:"1920x1080", quality:"high", model:"gpt"}])
```

生成结果落在 `assets/image/`，然后在期数脚本的场景里加一条：

```python
"bg": "assets/image/ep2_bg_hook_20260929185814.png",
```

**未配置 `bg` 的场景自动回退到程序化渐变**，所以两期可以混用同一套引擎。

### 关键实现细节（都是踩过的坑）

**① 背景缓存必须按"背景种类"各建一份。**
`build_video` 原先只建一份缓存，而且是在任何场景背景设置之前，
于是所有缓存帧都是程序化渐变 —— 即使渲染前正确设置了 AI 背景，
取到的仍是缓存里的旧渐变，成片里根本看不到 AI 图。
现在 `build_bg_caches()` 每种背景一份缓存，按场景绘制窗口的中点分配帧。

**② 渲染函数可能返回新图，调用处必须接收返回值。**
`scrim()` 要合成一层半透明暗底，必须返回新对象。
所有调用点都写成 `img = render.RENDERERS[...](img, ...)`；
漏掉一处就会静默丢效果（实测踩过）。

**③ AI 图只替换"底色层"，不动运动设计。**
星点、散景、前景光斑照旧绘制并参与四层视差 ——
运动设计是这个引擎真正的价值，不能被一张静态图取代。
照片层用 `PAR_PHOTO = 0.22` 做缓慢位移，`PHOTO_SCRIM = 0.62` 压暗保证文字可读。

**④ 背景与内容不要重复表达。**
`gap` 场景的 AI 图本身就画了"两条曲线分叉"，我原先又叠了一张同构图表面板，
两套曲线压在一起观感很乱。现在横屏直接用背景表达概念、只保留文字说明与图例
（`draw_panel = vert or _bg_image is None`）；竖屏背景被裁切，仍保留自己的面板。

### 前期准备：让 MCP 认出项目

图片生成工具要求 target_dir 下有 `.maker-mcp/config.json`（含 `project_id`、`user_id`）。
首次调用若报 `Cannot resolve user_id`，补上这两个字段即可。

## 多期结构

```bash
python narrate.py --ep=2      # 生成某一期配音与时间轴
python build.py --ep=2        # 构建某一期（横屏）
python build.py --ep=2 --format=v   # 竖屏
python verify_output.py 2 h   # 验收（期数 画幅）
python test_text_overlap.py 2 # 文字压盖检查
python test_formats.py 2      # 双画幅冒烟 + 元素越界审计
python test_content_identity.py  # 画面文案必须来自当期（防串期）
python audit_hardcoded.py     # 渲染函数里是否写死了文案
python test_readability.py 2  # 文字与背景的对比度
python verify_bg_source.py 2  # 确认 AI 背景真的进了帧
```

- `script.py` 是**期数分发器**：`CURRENT_EP` 指定默认期，`--ep=N` 覆盖
- `episodes/epN.py` 每期一个文件，含 `VIDEO`（标题/音色/语速/时序参数）与 `SCENES`
- 每期独立的时间轴与配音目录：`build/timeline_epN.json`、`build/audio_epN/`
- 换期不会误用上一期的音频（这是分目录的原因）

### 内容必须数据驱动（重要）

渲染函数**不得写死文案**，只能从 `sc[...]` 取或 `sc.get(...) or 默认值`。

第 2 期第一版就栽在这里：`render_hook` 里写死了 `text = "什么是大语言模型"`，
第 2 期复用它之后，开场画出的**是第 1 期的标题**，与旁白完全对不上。
`audit_hardcoded.py` 会用 AST 区分"危险写死"与"安全回退默认值"，
`test_content_identity.py` 会检查各期画面里不出现别的期专属文案。

### 新增一期要做什么

1. 复制 `episodes/ep2.py` 改文案（`title / kicker / subtitle / narration / visual / min_dur`）
2. 若需要新的视觉形式，在 `render.py` 里加一个 `render_xxx` 并注册到 `RENDERERS`
3. 跑 `calibrate_rate.py --ep=N` 确定语速，再 `narrate.py` + `build.py`

**已有视觉组件**（跨期复用）：
`hook` `predict` `token` `attention` `train` `outro`（第 1 期）
+ `conf` `fluent` `gap` `reason`（第 2 期）

# AI 科普短片 —— 引擎说明

## 快速开始

```bash
# 依赖（独立 ffmpeg 二进制 + 微软 Edge TTS，不污染系统环境）
python -m pip install imageio-ffmpeg edge-tts

# 1) 生成配音 + 时间轴（改文案或换音色后需要重跑）
python narrate.py

# 2) 渲染成片（默认 2x 超采样抗锯齿，约 7 分钟）
python build.py

# 3) 只要静帧预览，不编码视频（快）
python build.py --preview

# 4) 关闭超采样（快 4 倍，但边缘有锯齿）、或提高到 3x
python build.py --ss=1
python build.py --ss=3
```

## 分辨率无关架构（重要）

布局代码**永远只写 1920×1080 的逻辑坐标**，由绘图层统一换算到设备像素：

```python
render.set_scale(2.0, (1920, 1080))   # 设备尺寸变成 3840x2160
# 布局代码不变；S(v) 换算单个值，ScaledDraw 自动换算绘图坐标
```

- `S(v)` —— 逻辑像素 → 设备像素
- `sd(draw)` —— 包装 `ImageDraw`，只缩放**定位参数**（坐标/包围盒），
  颜色、文本、角度、线宽保持原样
- `font(size)` —— 传逻辑字号，内部按 SCALE 加载并缓存设备尺寸字体
- `ScaledDraw` 的 `textlength` / `textbbox` **返回逻辑值**（结果除以 SCALE），
  因此 `tw()` 量出的宽度可与布局坐标直接相加

**为什么不用脚本自动改写坐标常量**：`render.py` 里有 472 个数字字面量，
其中混着时间常数（`t * 0.23`）、比例系数、颜色分量。机械改写会静默破坏动画时序
（不报错，但画面错乱），所以在绘图层做变换是唯一可靠的做法。

**收益**：4K、超采样、任意输出尺寸都只需改一个参数，不再需要手改 6 个场景的坐标。

## 竖屏现状（未完成，已显式拦住）

`python build.py --format=v` 会**拒绝执行**并提示原因 —— 这是刻意的，避免产出坏片子。

**已完成**：适配层。`set_scale(scale, logical_wh, profile)` 支持任意画幅：

- `S / SX / SY` —— 标量 / 横向 / 纵向像素换算
- `ScaledDraw` —— 自动换算绘图坐标与线宽；查询类方法（`textlength`/`textbbox`）返回参照单位
- `PROFILES` —— 横屏 / 竖屏两套版式档案（边距、标题字号、正文起点、字幕位置、对齐）
- `AV()` —— 当前版式的可用宽度（场景里若直接用 `W`，会把**设备宽度**当成可用宽度，
  竖屏下导致居中元素被裁）
- 横屏走新路径后**几何完全未变**：实测特征质心偏移 < 1.3px、包围盒一致

**未完成**：6 个场景的内容构图仍是 1920 宽的横屏版式。各场景元素是按横向排布的
（「注意力」的决策面板在 x=1252、「预测」的概率条在 x=1160、末尾场景的概率环居中，
但标题用 `AV()` 居中而正文用固定 x），压进 1080 宽会裁掉两侧 ——
实测竖屏下出现：标题右侧被切、关注度百分比叠在标题上、条形图百分比溢出画布。

**结论（比代码更重要）**：**自动适配解决不了宽高比差异**。横屏内容改竖屏必须
**逐场景重新构图**（横向并排改纵向堆叠、放大字号、重排信息层级、把前 3 秒做成钩子），
这不是加个缩放参数能得到的。本轮把适配层做成了通用能力，竖屏内容设计留作独立一轮。
加 `--allow-draft` 可以看草稿，但当前不可用。

## 抗锯齿（超采样）

实测发现 **Pillow 的几何图元完全没有抗锯齿**：

| 图元 | 边缘扫描线 | 中间灰像素 |
|---|---|---|
| ellipse / rounded_rectangle / polygon | `[0,0,0,255,255]` | **0 个** |
| 2x 超采样后 | `[0,1,0,14,241,255]` | 7 个 |

所以用 2 倍分辨率绘制再 LANCZOS 降采样。代价与收益：

| 倍率 | 单帧耗时 | 全片渲染 | 边缘质量 |
|---|---|---|---|
| 1x | 42ms | 2.1 分钟 | 硬锯齿 |
| **2x** | **201ms** | **7.3 分钟** | 单像素平滑过渡 |
| 3x | ~450ms | ~15 分钟 | 与 2x 差别很小（已收敛） |

配套优化：`background()` 在 4K 下原本要 1052ms/帧，改为「低频部分半分辨率计算
+ 可分离 1D 高斯 + 星点在输出分辨率单独绘制」后降到约 250ms（**4.3 倍**，色差 0.4）。
另外背景是按 2~3fps 预渲染后插值复用的，否则单帧成本还要再翻倍。

## 转场（已设计）

原先 5 次场景切换都是「整体淡出到黑 + 0.28s 间隔 + 淡入」。实测每次有约
**0.37s 画面接近全黑**（合计 1.83s），屏幕上会明显闪黑，且全部是同一种处理。

`audit_transitions.py` 量化后改为：相邻场景在 `XFADE=0.42s` 内直接交叠，
绘制窗口互相重叠、**不留间隙**；并按语义给不同类型：

| 转场 | 类型 | 做法 |
|---|---|---|
| hook → predict | `sweep` | 斜向擦除 + 边界光带扫过 |
| predict → token | `wipe` | 竖向擦除 |
| token → context | `dip` | 后场景轻微放大推入 + 叠化 |
| context → train | `sweep` | 同上 |
| train → outro | `wipe` | 同上 |

擦除掩码在 1/32 分辨率生成再放大（只影响边界锐利度，肉眼不可辨，但快很多）。
字幕在**转场合成之后**绘制，避免被叠化稀释或重复绘制。

实测（`verify_transitions.py`）：

| 指标 | 改造前 | 改造后 |
|---|---|---|
| 转场处最暗/两端亮度 | **0.000**（全黑） | **0.903** |
| 近黑时长 | 1.83s | **0s** |
| 转场类型数 | 1 | **3** |

## 景深：4 层视差

| 层 | 内容 | 视差系数 | t=0→6s 位移 |
|---|---|---|---|
| 远景 | 渐变 + 光斑 + 网格 | 0.55 | −14.2 px |
| 中景 | 星点（闪烁） | 0.30 | −7.7 px |
| 近景 | 散景光斑（大而虚） | 0.08 | −2.1 px |
| **极近景** | **大颗虚焦光斑** | **1.35** | **−34.8 px** |

极近景的视差系数 **> 1**（比远景移动更快），制造"贴着镜头"的空间感；
其位置刻意避开底部字幕带，不干扰字幕可读性。前景/远景速度比 **2.45×**。
四层同样由统一 `camera_pos(t)` 驱动 —— 同向、只差快慢才有纵深，
各层用各自频率乱动只会显得杂乱。

## 景深 / 视差（背景层）

背景拆成三层，由**统一摄影机** `camera_pos(t)` 驱动，层间速度差产生纵深：

| 层 | 内容 | 视差系数 | t=0→6s 位移 |
|---|---|---|---|
| 远景 | 渐变 + 光斑 + 网格 | 0.55 | −14.2 px |
| 中景 | 星点（闪烁） | 0.30 | −7.7 px |
| 近景 | 散景光斑（大而虚） | 0.08 | −2.1 px |

远/近速度比 **6.9x**。关键点是三层**同向、只差快慢** —— 各层用各自的频率乱动
只会显得杂乱，不会产生纵深。

远景色调变化极慢，按 `CAM_SNAP` 像素量化后缓存复用（量化残差用平移补偿，
保证运动连续），因此视差几乎不增加成本。

暗角烘进远景层，让中近景元素更跳出来。**强度刻意压得很低**：实测
0.42 会让四角降到中心的 30%、整体亮度掉 20%，画面明显发闷；现在
`VIG_STRENGTH=0.12 / VIG_FLOOR=0.90`，四角/中心 0.59（旧版 0.67），
亮度仅 −4.6%，只做视觉框而不压暗画面。

## 运动设计

原先所有入场都用同一个 `ease_out` —— 这是程序化动画最典型的廉价感来源。
现在用 `stagger()` 把元素**错帧**入场，并按语义选曲线：

| 档位 | 曲线 | 用途 |
|---|---|---|
| `heavy` | ease_out_quart | 大块元素：起步快、收尾长 |
| `light` | ease_out_expo | 快速出现的小元素 |
| `pop` | ease_out_back | 卡片、标签（带回弹） |
| `elastic` | ease_out_elastic | 强调元素（光核、首名概率条） |
| `soft` | ease_in_out | 平滑过渡、副标题 |
| `bounce` | ease_out_bounce | 落体回弹 |

配合 `wipe()`（下划线扫过带过冲）、`count_up()`（百分比数字滚动）、
`pulse()`（静止元素轻微呼吸，避免"死"）。

改完后的实测（`audit_motion.py`）：

| 场景 | 用到的曲线档位数 | 明细 |
|---|---|---|
| hook | 3 | elastic + quart + in_out |
| predict | 5 | expo×10, quart×8, elastic×5, in_out, back |
| token | 4 | in_out×7, quart×3, back×3, expo |
| context | 3 | quart×4, back×4, in_out |
| train | 3 | quart×3, back×2, in_out |
| outro | 5 | quart×17, expo×16, back×15, in_out×13, elastic |

错帧跨度：概率条 0.52s、词卡 0.34s、流程节点 0.68s、Token 0.52s
（全部元素同时到达 = 0s，是廉价感的直接来源）。

### 踩过的三个坑（都留了回归测试）

1. **`S()` 被当成通用缩放用** —— 它实际乘的是**纵向**比例。竖屏下 fy=1.778、fx=0.5625，
   对 x 用 `S()` 会把宽度放大 **3.2 倍**，图形整个溢出。现在 x 专用 `SX()`，
   包围盒统一走 `scaled_box()`（按轴向分别换算）。
   *这是竖屏第一版彻底失败的根因，肉眼只看到"图很大"，量出来才知道是 3.2 倍。*

2. **字体缩放与量测不一致** —— 字体按 fy 放大、`textlength` 又按 fx 还原，
   两者相差 fy/fx=3.16 倍，`_fit_title_size` 据此把标题**误缩到 48px**。
   改为：字体只按 `SCALE` 缩放，`textlength` 也只除以 `SCALE`。

3. **`Y()` 与手写竖屏坐标叠加** —— 竖屏坐标已是绝对值，再被 `Y()` 拉伸会二次位移。
   改为由 `body_stretch` 标志显式控制（而不是靠"caption_y 恰好相等"这种隐式巧合，
   那种写法一改字幕位置就会出错）。

## 改文案重跑

**只需要改 `script.py`**，然后重跑 `narrate.py` + `build.py`。

`script.py` 里每个场景声明：`title / subtitle / narration / visual / min_dur`。
旁白时长由 TTS 实测决定，场景时长自动取 `max(旁白时长 + pad, min_dur)`，
整片总长也随之自动重算 —— 不需要手改任何时间数字。

```python
VIDEO = {
    "voice": "zh-CN-XiaoxiaoNeural",   # 音色（女声晓晓）
    "rate":  "+16%",                   # 语速，主要用这个控制总时长
    "head": 0.45, "gap": 0.28, "tail": 0.90, "pad": 0.40,
}
```

**换音色前先跑 `python calibrate_rate.py`** —— 它会测出该音色在各语速下的成片长度，
直接告诉你该用哪一档（晓晓：+16%→60.7s，且 +18% 以上总长不再变化，
因为多数场景由 `min_dur` 下限主导）。

想换成竖屏，只需改 `VIDEO["width"]/["height"]`，并把各场景里的 X 坐标改为居中布局
（布局常量集中在 `render.py` 顶部：`Y_TITLE / LH_TITLE / TITLE_BLOCK_H`）。

## 文件说明

| 文件 | 作用 |
|---|---|
| `script.py` | **分镜脚本（单一事实来源）**：文案、音色、语速、各场景时长下限 |

## 实现要点

**音频与时间轴**
- Edge-TTS 现已把 `WordBoundary` 降级为 `SentenceBoundary`（句级 offset/duration + 原文）。
  字幕时间轴的做法是：用句级锚点作为骨架，句内按「字数 + 标点停顿权重」细分到每个字，
  再按标点优先断行合成 6~14 字的字幕行。实测 32 条字幕覆盖旁白总长的 99%。
- 音轨不交给 ffmpeg 滤镜拼接，而是在 Python 里解码 6 段 MP3 为 24kHz 单声道 PCM，
  按 `timeline.json` 的 `start` 直接写进一条静音底轨 —— 采样级精确，无累计漂移。

**渲染**
- 画面是时间的纯函数 `render(img, t, dur, scene, ctx)`：任意时刻都能独立出帧，
  因此可以抽静帧预览、可以流式编码（恒定内存）。
- 帧数据经 stdin 管道流式喂给 ffmpeg（libx264 CRF 18），不落盘中转，
  60 秒 1816 帧约 100 秒渲染完，峰值内存只有几帧的缓冲。
- 背景（渐变 + 光斑 + 网格 + 星点）按 10fps 预渲染后插值复用，避免每帧重算。

**踩过并修掉的坑**（都留了回归测试）
1. `make_glow` 早期版本是「整片加性抬亮」，填充率恰好 1.0000 —— 把辉光窗口渲染成了
   一个青蓝色实心方块。改为径向衰减 × 局部模糊亮部，跨窗口边界跳变降到 0。
2. 字幕条的时间轴是全片绝对时间，但调用方传的是场景内相对时间 → 字幕永远匹配不上，
   成片里**一条字幕都没有**。是 `verify_output.py` 的抽帧检查抓出来的。
3. 损失曲线 y 轴方向映射写反，画成了上升曲线；同时曲线面板盖住了后半段流程节点。
4. 标题块高度没有统一约定，各场景正文按硬编码 y 排布 → 大面积压盖。
   现在由 `Y_TITLE / TITLE_BLOCK_H` 统一约束，并由 `check_layout.py` 自动校验。
